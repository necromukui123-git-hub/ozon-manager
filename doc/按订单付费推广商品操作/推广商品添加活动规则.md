# CPO 状态迁移自动化规则

本文件只描述 `Search CPO -> Morkovsk` 的自动迁移规则。  
同一页面上的“人工批量报名”请看：`doc\按订单付费推广商品操作\CPO商品批量报名.md`。

## 接口
1. `list`
   - 文件：`doc\按订单付费推广商品操作\list.txt`
   - 用途：刷新按订单付费推广商品列表，获取商品基础状态和明细。
2. `search_promo_availability`
   - 文件：`doc\按订单付费推广商品操作\search_promo_availability.txt`
   - 用途：判断商品当前是否进入可迁移状态。
3. `enable`
   - 文件：`doc\按订单付费推广商品操作\enable.txt`
   - 用途：在退出其它促销活动后，显式开启商品推广。
4. `batch_enable`
   - 文件：`doc\按订单付费推广商品操作\batch_enable.txt`
   - 用途：将商品加入固定目标活动 `Morkovsk`。
5. `deactivate`
    - 文件：`doc\按订单付费推广商品操作\deactivate.txt`
    - 用途：批量将商品从店铺促销活动中删除；

## 状态定义
1. `state1`
   - `searchPromoStatus = SEARCH_PROMO_STATUS_DISABLED`
   - `carrotsStatus = CARROTS_STATUS_DISABLED`
   - `availability_promo = false`
2. `state2`
   - `searchPromoStatus = SEARCH_PROMO_STATUS_DISABLED`
   - `carrotsStatus = CARROTS_STATUS_DISABLED`
   - `availability_promo = true`
3. `state3_trigger`
   - 商品历史上已经进入过 `state2`
   - 当前刷新时 `searchPromoStatus = SEARCH_PROMO_STATUS_ENABLED`
   - 这个状态只作为历史漏跑后的兜底，不是主触发路径
4. `morkovsk_joined`
   - 已成功加入 `Morkovsk`

## 执行规则
1. 自动化运行先刷新 `list`，再同步 `search_promo_availability`，然后重新计算每个商品的规则状态。
2. `state1` 商品只做一件事：加入用户在 Search CPO 页面里已经保存好的默认官方/店铺活动。
3. `state2` 是主触发状态。一旦检测到 `state2`，就进入迁移后半段：
   - 先全量同步官方和店铺活动清单
   - 再刷新这些活动的商品成员关系
   - 按 SKU 找出商品当前命中的全部官方/店铺活动
   - 将商品从这些命中的活动中退出
4. 如果退出阶段成功，或者全量同步后没有发现该商品命中任何活动，则继续执行 `enable`。
5. `enable` 成功后，调用 `batch_enable` 把商品加入固定目标活动 `Morkovsk`。
6. `state3_trigger` 商品执行与 `state2` 相同的迁移后半段，用于收敛历史漏跑或中断后已经变成 enabled 的商品。
7. 成功加入 `Morkovsk` 后，商品状态记为 `morkovsk_joined`，后续不再重复处理。

## 执行说明
1. `state2` 到来的时间未知，所以自动化需要重复运行，持续检测。
2. 退出范围不是“初始活动集合”，而是当前同步到的全部官方/店铺活动里，该 SKU 实际命中的活动。
3. 若店铺活动退出返回“当前商品不在该活动中”，该结果视为可继续的跳过，不阻断 `enable` 和 `Morkovsk`。
4. 若活动清单同步失败、活动商品刷新失败、真实退出失败、`enable` 失败或 `batch_enable` 失败，都要在自动化详情里逐商品记录原因。
5. `Morkovsk` 是固定目标，不通过普通活动 ID 配置。
